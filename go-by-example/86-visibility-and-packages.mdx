# Visibilidade e Packages

Em Go, a primeira letra do identificador define se ele pode ser usado por outro package. Maiúscula significa exportado; minúscula significa não exportado. Não existe uma palavra-chave `public` ou `private`.

type Product struct {
    ID    string

func NewProduct(id string, price int) Product {
    return Product{ID: id, price: price}

func (p Product) Price() int {
    return p.price
}

func normalizeID(id string) string {
    return id
}`}

## A regra que vale memorizar

Visibilidade em Go é decidida pelo identificador:

- `Product`, `NewProduct` e `Price` são exportados.
- `price` e `normalizeID` não são exportados.

O package deve expor uma API pequena. Se todo campo e toda função são públicos, qualquer mudança interna vira uma mudança de contrato.

## Armadilhas comuns

- Exportar campos só para facilitar um teste ou um JSON, sem decidir se eles realmente fazem parte do contrato.
- Criar um package `utils` genérico em vez de colocar o comportamento perto do domínio que o usa.
- Confundir package com namespace de classe: em Go, composição entre packages é feita por funções, tipos e interfaces exportados.

Em um projeto real, coloque o código acima em `catalog/product.go` e importe o package com `catalog.NewProduct(...)`. O próximo passo é aprender a organizar módulos e testar o contrato público.
