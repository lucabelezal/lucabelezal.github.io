Enviar e receber bloqueiam até o outro lado aparecer — às vezes você só quer **tentar**: se não der na hora, segue o fluxo. É o papel do **`default`** num `select`: quando nenhum caso está pronto, o `default` roda imediatamente. Receive, send e combinações viram "tentativas" sem travar.

## A regra do default

Um `select` **com** `default` nunca bloqueia: se nenhum case está pronto, o default roda na hora. Um `select` **sem** default bloqueia até alguém ficar pronto. Essa única diferença transforma operações bloqueantes em tentativas:

```go
select {
case v := <-ch:
    // chegou algo
default:
    // nada agora — segue em frente
}
```

É o equivalente a um *try-receive*: útil para *polling* leve, checagem de sinal e "faça se der, senão segue".

## Em código real

- **Polling de sinal de parada**: no loop de um worker, checar `done` sem bloquear entre tarefas.
- **Preencher buffer se houver espaço**: enviar para um semáforo `chan struct{}` bufferizado sem travar quando está cheio.
- **Fallbacks**: tentar o canal rápido; se vazio, usar o valor default.

Cuidado com o exagero: *polling* com `default` num laço quente queima CPU. Se a goroutine deve **esperar** por algo, prefira um receive bloqueante (ou `select` sem default) — o padrão de [Select](select).

## Armadilhas comuns

- **`default` em loop apertado**: roda milhões de vezes sem trabalho — CPU a 100%. Para esperar de verdade, bloqueie (sem default).
- **Achar que é "assíncrono"**: é **síncrono não-bloqueante** — tenta agora e segue. Não há fila mágica.
- **Esquecer que canal fechado está "pronto"**: um receive num canal fechado devolve zero value **na hora** (sem bloquear) — o case roda mesmo com o default presente, com valor lixo. Trate o `ok`.
- **Multi-way com todos vazios**: cai no default — comportamento certo, mas confirme que era o que você queria (e não um receive bloqueante esquecido).
