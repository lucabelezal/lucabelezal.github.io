Quando `strings.Contains` não basta — o padrão é "letra p, um ou mais minúsculas, e depois ch" — você precisa de **expressão regular**. O pacote `regexp` de Go implementa a sintaxe **RE2**: poderosa, sem *backreferences* nem *lookahead* (de propósito — RE2 roda em tempo linear, garantindo que uma regex maliciosa não trave seu servidor).

## Compile uma vez, use muitas

`MatchString` compila o padrão a cada chamada — ok para um teste isolado, caro num laço. O idioma é **compilar no nível de package**:

```go
var corHex = regexp.MustCompile(`^#?([0-9a-fA-F]{3}|[0-9a-fA-F]{6})$`)
```

O `MustCompile` faz duas coisas: compila uma vez (no startup) e transforma padrão inválido em panic — certo, porque uma regex literal errada é bug. Em Go, use **raw strings** (crases) para padrões e evite a dupla fuga de barras: `` `\d+` `` em vez de `"\\d+"`.

## O que cada família de método devolve

| Método | Devolve |
|---|---|
| `MatchString` | `bool` (casa ou não) |
| `FindString` / `FindAllString` | o match (ou todos) |
| `FindStringIndex` / `SubmatchIndex` | posições `[início, fim)` (por grupo no `Submatch`) |
| `ReplaceAllString` / `ReplaceAllFunc` | texto com os matches trocados |
| `Split` | pedaços em volta dos matches |

Sem match, `Find...` devolve `nil`/`-1` — não um erro. Cheque o retorno em vez de assumir.

## Limite de RE2: sem backreference nem lookahead

Se você vem de PCRE/JavaScript, vai sentir falta de `\1` (backreference) e `(?=...)` (lookahead). É **de propósito**: essas features exigem retrocesso que pode explodir exponencialmente. RE2 garante tempo linear no tamanho da entrada — uma regex Go não consegue travar seu servidor. Quando você realmente precisa de backreference, o caminho é um parser de verdade, não regex.

## Em código real

- **Validação**: e-mail, CEP, formato (`regexp.MustCompile` + `MatchString`).
- **Extração**: achar tokens num log com `FindAllStringSubmatch` (grupos dão o dado já separado).
- **Sanitização**: `ReplaceAllString` para limpar texto; `ReplaceAllFunc` com uma função customizada.
- Cuidado com o outro extremo: regex não é para **parsear HTML/JSON/linguagens**. Para isso existem parsers próprios (a próxima página, [JSON](json), é o exemplo). Regex em markup quebrado gera bugs sutis — use a ferramenta certa.

## Armadilhas comuns

- **Recompilar a cada chamada**: `MatchString` direto num laço compila o padrão N vezes. Compile uma vez (`MustCompile` no package).
- **Esperar backreference/lookahead**: não existem em RE2. Refatore o padrão ou use um parser.
- **Grupos demais**: cada `(...)` vira uma posição em `SubmatchIndex`. Se você só quer "casa ou não", sem grupos, o índice fica mais simples.
- **Ignorar o erro de sintaxe**: `Compile` devolve erro para padrão inválido (`[` sem fechar, etc.). Sempre trate ou use `MustCompile`.
- **`*` e `+` são gulosos**: `p.*ch` em `peach punch` casa até o **último** `ch`, não o primeiro. Para casar o mínimo, ajuste o padrão (ex.: `p[^ ]*ch`).

## Pratique

1. **Reproduza**: rode `regular-expressions.go` e interprete `all: [[0 5 1 3] ...]` — cada par é `[match inicio, match fim, grupo inicio, grupo fim]`.
2. **Modifique**: valide um CEP brasileiro (`^\d{5}-?\d{3}$`) com `MustCompile` + `MatchString`; depois extraia todos os números de um texto com `FindAllString`.
3. **Aplique**: escreva `func mascarar(s string) string` que troca dígitos de cartão por `*` usando `ReplaceAllString` com `\d` — e faça a versão com `ReplaceAllFunc`.
