Listas indexam por número; o mundo indexa por **chave** — "saldo do cliente 42", "status do pedido #7". O **map** é o dicionário de Go: associa chaves a valores, cresce sozinho e responde à pergunta mais importante de uma busca: *a chave existe?* A resposta a essa pergunta — e não apenas "que valor tem?" — é o que separa quem entende map de quem só copia.

## A pergunta certa: a chave existe?

`m["k3"]` devolve `0` tanto para "chave ausente" quanto para "chave presente com valor 0". Para distinguir, use o **comma-ok**:

```go
if v, ok := m["k3"]; ok {
    // chave existe, v é o valor
} else {
    // chave não existe
}
```

É o mesmo padrão `if x, ok := ...; ok` do [type assertion](interfaces). Regra: quando o valor pode ser `0`/`""`/`false` legítimo, o `ok` é obrigatório — contar ocorrências ou checar presença sem ele é bug silencioso.

## Map é referência — mas cuidado com o `nil`

Assim como slices, um map carrega uma referência interna: passá-lo para uma função **muta o original**, sem ponteiro. Duas regras que pegam todo mundo:

- **Ler de um map `nil` é seguro** (devolve zero value): `var m map[string]int` + `m["a"]` → `0`.
- **Escrever num map `nil` é *panic***: `m["a"] = 1` com `m == nil` derruba o programa. Por isso `make` (ou literal) antes de escrever — o *zero value* de map **não** é utilizável, diferente de slice.

## Ordem de iteração é aleatória (de propósito)

`range` sobre um map percorre as chaves em ordem **arbitrária**, que muda a cada iteração. O Go faz isso de propósito para ninguém depender de ordem. Se você precisa de ordem: extraia as chaves com `maps.Keys`, ordene com `slices.Sort`, e itere nessa ordem.

## Chaves comparáveis, valores qualquer coisa

Chaves podem ser qualquer tipo **comparável** com `==`: `string`, `int`, `bool`, **structs** (úteis como chave composta), ponteiros. Não podem: slices, maps, funções. Valores podem ser qualquer tipo — inclusive outro map ou slice.

## Maps não se comparam com `==`

`m1 == m2` só compila se comparar com `nil`. Para comparar conteúdo, `maps.Equal(n, n2)` (e `maps.EqualFunc` para valores com critério próprio).

## Armadilhas comuns

- **Escrever em map `nil`**: `var m map[string]int; m["x"] = 1` → *panic: assignment to entry in nil map*. Sempre `make` antes de escrever.
- **Confiar no zero value para "não existe"**: `if m["k3"] > 0` falha quando o valor legítimo é 0. Use comma-ok.
- **Depender da ordem do `range`**: iteração de map é arbitrária. Ordene as chaves quando precisar de sequência.
- **Copiar map com `=`**: `n2 := n` não copia nada — os dois apontam para o mesmo map; mutar um muda o outro. Use `maps.Clone`.
- **Usar slice como chave**: não compila (slice não é comparável). Para "chave composta", use struct ou serialize.

## Pratique

1. **Reproduza**: rode `maps.go` e explique por que `v3` é `0` e `prs` é `false`.
2. **Modifique**: adicione `m["k3"] = 0` e busque `k3` com comma-ok — perceba a diferença entre `v3` e `prs`. Depois itere com `range` e rode 3 vezes: a ordem muda.
3. **Aplique**: escreva um contador de palavras (`map[string]int`) que usa comma-ok para decidir se incrementa ou inicializa — depois reescreva com a leitura direta `m[w]++` (funciona porque ausente = 0). Compare.
