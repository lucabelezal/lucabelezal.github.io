Go não tem a palavra `enum` — mas tem o padrão: um **tipo com valores constantes**. Você declara `type ServerState int` e as constantes com **`iota`**, que numera automaticamente. O que transforma isso num enum de verdade é a **segurança de tipo**: um `int` cru não vira `ServerState` sem conversão, e `switch`/`String()` fecham o círculo.

## Por que `iota` e tipo novo, não constantes soltas

Sem o tipo, você teria `const Idle = 0` — e qualquer `int` com valor `0` seria \"idle\" por acidente. Com `type ServerState int` + constantes tipadas, o compilador **recusa** `transition(5)` e `transition(algumInt)` — um `int` não é um `ServerState` sem conversão explícita. É a segurança do enum: estados válidos são só os que você declarou.

`iota` é conveniente, mas preste atenção: se você inserir uma linha no meio do bloco, **todos os valores seguintes mudam** (a numeração é posicional). Para enums com valores que precisam ser estáveis (guardados em banco, serializados), atribua números explícitos:

```go
const (
    StateIdle      ServerState = iota // 0
    StateConnected                    // 1
    StateError                        // 2
)
```

## String() e a ferramenta stringer

Implementar `String()` manualmente para muitos valores é repetitivo — e o nome do estado pode divergir do código. A ferramenta oficial `stringer` gera o método para você:

```go
//go:generate stringer -type=ServerState
```

roda o código, que produz o `String()` automaticamente. (É a diretiva de geração do ecossistema — complementar ao `//go:embed` de [Diretiva Embed](embed-directive).)

## Em código real

Enums tipados aparecem em todo estado de máquina: status de pedido, estado de conexão, nível de log, tipo de evento. O trio `type + iota + String()` é o padrão; o map de nomes também permite o caminho inverso (string → enum) quando você faz parse de input.

## Armadilhas comuns

- **`iota` reordenada muda valores**: inserir uma constante no meio renumerou tudo. Para valores persistidos, use números explícitos.
- **Achar que `switch` é obrigatório**: `String()` via map (como aqui) é mais simples; `switch` só quando cada caso tem lógica.
- **Valor zero não declarado**: `iota` começa em 0 — se `0` deveria ser \"inválido\", declare o primeiro caso como `StateUnknown ServerState = iota` e use o resto a partir daí.
- **Esquecer o `String()`**: imprimir um enum sem `Stringer` mostra o número — difícil de debugar.
- **`panic` no default sem motivo**: só faz sentido quando o enum é fechado (não deveria ter valores desconhecidos); para entrada externa, retorne erro em vez de panic.

## Pratique

1. **Reproduza**: rode `enums.go` e explique por que `ns2` é \"idle\" (a transição de `connected`).
2. **Modifique**: adicione um `StateShuttingDown` (novo iota) e sua transição; veja os valores mudarem.
3. **Aplique**: crie `type StatusPedido int` com `nova_pagamento`, `pago`, `enviado`, `entregue` — com `String()` e uma função `proximo(p StatusPedido) StatusPedido` que ignora pedidos entregues (retorna o mesmo).
