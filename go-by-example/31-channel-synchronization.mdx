Esperar uma goroutine terminar é um dos atos mais comuns da concorrência. Uma forma — já vista — é o [WaitGroup](waitgroups). Outra é um **channel de sinalização**: a goroutine envia ao terminar, e o chamador bloqueia no receive até o sinal chegar. O channel vira um "avise-me quando acabar".

import (

func worker(done chan bool) {
    fmt.Print("working...")

    done <- true
}
func main() {
    done := make(chan bool, 1)
    go worker(done)
    <-done
}`}

## Channel de sinalização × WaitGroup

| | Channel de sinal | WaitGroup |
|---|---|---|
| Sinaliza | "terminou" (1 goroutine ou a última) | "N goroutines terminaram" |
| Contagem | Não tem — é um evento | Contador com `Add`/`Done` |
| Valor | Pode carregar um dado (resultado!) | Só contagem |
| Uso típico | Sincronizar pares, notificar evento | Esperar um grupo de workers |

O channel de sinalização é natural quando a conclusão **carrega um valor** — o "terminei" e o "resultado" chegam juntos: `resultado := <-done`. Para muitos workers, o [WaitGroup](waitgroups) é a ferramenta certa; para "a main espera esta goroutine específica", o channel resolve.

## Em código real

O padrão "goroutine notifica conclusão" é a base de muitos fluxos: um worker que avisa o pool, um produtor que sinaliza "acabei de gerar", um service que aguarda o `done` de inicialização. Combine com `select` (páginas [Select](select)) para esperar **vários** sinais ao mesmo tempo — ou um sinal OU um timeout.

## Armadilhas comuns

- **Esquecer o receive**: `go worker(done)` sem `<-done` — a main não espera e o programa termina cedo. A sincronização exige os dois lados.
- **Sinal sem buffer**: `done <- true` num channel sem buffer e sem receptor na hora **bloqueia** — se for o último ato do worker, ele trava. O buffer 1 (ou receptor pronto) evita.
- **Achar que o channel "guarda" o término**: o receive só desbloqueia quando o valor **chega**; enviar antes do trabalho acabar sinaliza cedo.
- **Misturar com WaitGroup à toa**: para uma goroutine, um channel basta; WaitGroup é para grupos.

## Pratique

1. **Reproduza**: rode `channel-synchronization.go`; remova o `<-done` e observe o comportamento.
2. **Modifique**: faça o worker enviar um **resultado** (`done <- 42`) em vez de bool e imprima o valor recebido.
3. **Aplique**: duas goroutines que sinalizam num channel compartilhado; a main recebe **duas** vezes (cada conclusão) antes de seguir.
