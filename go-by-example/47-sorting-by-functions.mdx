`sort` do jeito "ordem natural" não serve para structs nem para critérios como "por tamanho da string" ou "por idade". O **`slices.SortFunc`** resolve: você passa uma **função comparadora** — e o pacote decide a ordem chamando-a. É o padrão *callback* (página [Funções](functions)) aplicado à ordenação: o critério vira um dado que você injeta.

## A assinatura do comparador

```go
func(a, b T) int  // <0 → a vem antes; >0 → a vem depois; 0 → iguais
```

Você nunca chama o comparador — o `SortFunc` chama. E não precisa decorar regra de sinal: `cmp.Compare` produz o int certo para `cmp.Ordered`. Para ordem **decrescente**, inverta: `cmp.Compare(b, a)`.

O comparador também é onde entra a lógica que o `Sort` natural não tem:

```go
slices.SortFunc(pessoas, func(a, b Pessoa) int {
    if c := cmp.Compare(a.idade, b.idade); c != 0 {
        return c          // primário: idade
    }
    return cmp.Compare(a.nome, b.nome) // desempate: nome
})
```

Composto de critérios = comparadores encadeados. E `slices.SortStableFunc` mantém a ordem original de elementos "iguais" segundo o comparador.

## Em código real

`SortFunc` é o jeito Go de ordenar qualquer coisa: structs por campo, strings por tamanho/ignorando caixa (`strings.ToLower` no comparador), structs por múltiplos campos. É o mesmo espírito do `comparator` de Java e da `key` de Python, mas com o tipo preservado e sem reflexão.

## Armadilhas comuns

- **Comparador inconsistente**: se `cmp(a,b)` e `cmp(b,a)` não forem opostos (ex.: comparar só um lado, ou `float` com NaN), a ordenação vira comportamento indefinido. Faça comparadores **totais** e consistentes.
- **Esquecer o desempate**: comparar só a idade embaralha pessoas de mesma idade de forma arbitrária. Encadeie o segundo critério se a ordem final importa.
- **`<0`/`>0` confuso**: não invente regra; use `cmp.Compare` e a ordem fica óbvia.
- **Struct grande por valor**: `SortFunc` copia os elementos ao comparar. Para structs grandes, use `[]*Person` e compare `a.age` via ponteiro (dica da própria página de referência).
- **`SortFunc` num slice que não deve mudar**: ordena no lugar. Clone antes se precisar do original.

## Pratique

1. **Reproduza**: rode `sorting-by-functions.go` e explique a ordem dos fruits pelo comprimento.
2. **Modifique**: ordene `people` por **nome** (decrescente) e depois por idade com desempate por nome.
3. **Aplique**: ordene uma lista de produtos (`{nome, preco}`) primeiro por preço e depois por nome — e reflita onde um comparador limpo vale mais que reinventar o bubble sort.
