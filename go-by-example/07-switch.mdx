Quando uma decisão tem muitos caminhos, uma escada de `else if` fica difícil de ler. O **`switch`** de Go resolve isso — e vai além do que você conhece de outras linguagens: além de comparar valores, ele funciona **sem expressão** (para faixas e condições) e compara **tipos** (o *type switch*). E, ao contrário de C, não há `break` automático: cada `case` já encerra sozinho.

## Sem `break`: o comportamento que difere de C

Em C, cada `case` *cai* para o próximo a menos que você escreva `break`. Em Go, **cada `case` encerra o switch automaticamente** — é impossível esquecer o `break` e vazar para o próximo ramo. A palavra-chave `fallthrough` existe para forçar o comportamento de C, mas é rara e deve ser usada com cuidado, pois pula a avaliação do próximo `case`.

## Três switches, três propósitos

| Forma | Quando usar |
|---|---|
| `switch expressao { case valor: }` | Comparar um valor contra candidatos fixos |
| `switch { case condicao: }` | Várias condições/faxas (substitui `else if`) |
| `switch t := i.(type) { case tipo: }` | Descobrir o tipo dinâmico de um valor de interface |

A avaliação é de cima para baixo e o **primeiro `case` que casa vence** — em qualquer das três formas.

## Em código real

- **Type switch** é a ferramenta para lidar com `any` (o tipo vazio, visto em [Interfaces](interfaces)): funções de logging, serializadores e handlers que recebem payloads de tipos variados usam esse padrão para decidir como tratar cada caso.
- **Switch sem expressão** aparece em lógica de faixas e regras de negócio com muitas condições.
- **Switch com valores** é comum em parsing de comandos, estados e opções — você vai vê-lo de novo em [CLI com subcomandos](command-line-subcommands).

## Armadilhas comuns

- **Esperar *fallthrough***: se veio de C, esqueça — em Go o `case` não cai sozinho.
- **Usar faixas num `switch` com expressão**: `switch nota { case > 7: }` não compila. Para faixas, use `switch` **sem expressão**: `switch { case nota > 7: }`.
- **Esquecer o `default`**: não é erro, mas um `default` pega os casos inesperados — o que muitas vezes evita um bug silencioso.
- **Tratar `any` sem type switch**: converter `any` na mão com `.(int)` direto pode causar *panic* se o tipo não bater. O type switch é a forma segura.

## Pratique

1. **Reproduza**: rode `switch.go` e identifique qual das três formas de `switch` produziu cada linha da saída.
2. **Modifique**: adicione um `case` para `float64` na função `whatAmI` e chame `whatAmI(3.14)`. Depois remova o `break` mental e tente imaginar: o que precisaria mudar em Go para o `case` "vazar"?
3. **Aplique**: reescreva a cadeia `else if` da página de [If/Else](if-else) como um `switch` sem expressão. Compare as duas versões e decida qual prefere.
