Upload que precisa de um arquivo intermediário, um teste que grava num local isolado, um download parcial: trabalho que merece um arquivo — mas não um **nome** nem um **lar** permanente. O `os.CreateTemp` e o `os.MkdirTemp` criam arquivos/diretórios com **nome único aleatório**, permissões seguras, no diretório temporário do sistema. A regra que acompanha: você cria, usa e **limpa**.

## Por que não criar na mão?

`CreateTemp` existe porque "gerar um nome único" é mais difícil do que parece: dois processos podem escolher o mesmo nome (corrida), e o padrão "crie e depois abra" deixa uma janela de segurança. O `CreateTemp` cria com `O_EXCL` (falha se o nome já existir) — atômico e seguro. E os temporários já nascem com permissão `0600` (só você lê), diferente de um `os.Create` manual.

## O padrão completo

```go
f, err := os.CreateTemp("", "meuapp-")
if err != nil {
    return err
}
defer os.Remove(f.Name()) // limpeza garantida

// usa o arquivo...
f.Write(dados)
f.Sync()
f.Close() // fecha antes de remover em Windows
```

Em produção, o ciclo é **criar → usar → fechar → remover**, com `defer` no `Remove`. Em testes, `t.TempDir()` faz tudo isso sozinho (cria diretório temporário e o limpa no fim do teste) — não reinvente.

## Em código real

- **Testes**: `t.TempDir()` para isolar arquivos; `CreateTemp` para testar código que recebe um `*os.File`.
- **Uploads/downloads parciais**: baixar para um temporário e renomear para o destino só quando completo (escrita atômica aparente).
- **Processamento intermediário**: formatos que exigem arquivo (compressão, conversão) sem poluir o diretório de trabalho.

## Armadilhas comuns

- **Não limpar**: `CreateTemp` sem `Remove` acumula lixo no sistema. `defer os.Remove` logo após criar.
- **Remover antes de fechar (Windows)**: feche o arquivo antes de `Remove`/`RemoveAll`; em Unix funciona, no Windows falha.
- **Achar que o prefixo é o nome final**: `CreateTemp("", "sample")` gera `sample` + sufixo aleatório. Se você precisa do nome exato, temporário não é a ferramenta.
- **Escrever no diretório errado**: passar `""` usa o do sistema; se quiser "perto de mim", passe `"."`. Escolha de propósito.
- **`0666` vs `0600`**: para temporários com dado sensível, o padrão seguro (`0600`) do `CreateTemp` já vale — não force `0666` sem motivo.

## Pratique

1. **Reproduza**: rode `temporary-files-and-directories.go` e veja os nomes com sufixo aleatório; rode de novo — mudam.
2. **Modifique**: crie um arquivo temporário num diretório do projeto (`os.CreateTemp(".", "tmp-")`), escreva texto, leia de volta e remova — conferindo que ele some.
3. **Aplique**: escreva uma função que baixa (simulado) para um `CreateTemp`, escreve, chama `Sync`, `Close` e só então `Rename` para o destino final — o padrão de escrita "tudo ou nada".
