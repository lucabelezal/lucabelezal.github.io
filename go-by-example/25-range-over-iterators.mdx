Desde o Go 1.23, `for range` percorre mais que slices, maps e strings: ele itera sobre **funções**. Um *iterador* em Go é uma função com assinatura especial que "entrega" valores a um callback — e qualquer sequência vira `range`-ável: a sua lista encadeada, um gerador infinito de Fibonacci, linhas de um arquivo. É o `foreach` estendido a tipos customizados.

## O modelo de "push": quem controla o laço

Iteradores Go usam o modelo *push* com parada cooperativa: o iterador chama `yield` para empurrar cada valor, e o runtime (por trás do `range`) devolve `true` para continuar ou `false` quando o consumidor deu `break`/`return`. Por isso o `if !yield(v) { return }` aparece em todo iterador — é o mecanismo de **cancelamento antecipado**. A lista encadeada para de andar; o Fibonacci infinito encerra no `break`.

## Lazy: iterar sem materializar

A diferença prática para retornar um slice: o iterador **não aloca nem percorre nada até o `range` pedir**. `strings.SplitSeq` divide string por string sob demanda; um iterador de linhas de arquivo lê linha a linha. Quando você **quer** o material (ordenar, indexar, reutilizar), `slices.Collect`/`maps.Collect` materializam — o iterador é a fonte, o slice é o consumo.

## Em código real

- **Coleções próprias**: expor `All() iter.Seq[T]` em vez de vazar a estrutura interna.
- **Streams**: linhas de arquivo, eventos, paginação de API — itere sem carregar tudo.
- **Composição**: iteradores compõem com os helpers de `slices`/`maps`/`iter` (`iter.Map`, `iter.Filter` em versões novas).
- A sintaxe `func(yield func(T) bool)` também suporta **dois valores** (`iter.Seq2[K, V]`), o equivalente a `range` de map — para iteradores chave/valor.

## Armadilhas comuns

- **Esquecer o `if !yield(...) { return }`**: sem respeitar o `false`, um `break` do consumidor não para o iterador — ele continua gerando (e, num infinito, nunca acaba).
- **Retornar o iterador de uma função que captura estado mutável**: o iterador é avaliado quando o `range` roda; se o estado mudou antes, você itera o que está lá agora. Crie o iterador no momento do uso.
- **Achar que iterador é slice**: não dá para indexar. Precisa de índice? `slices.Collect` primeiro.
- **`range` sobre iterador nulo**: se a função devolve `nil` (em vez de um iterador válido), o `range` panica. Sempre devolva a função (mesmo que vazia).
- **Iterador que nunca devolve `false` no fim**: para sequências finitas, quando os valores acabam a função simplesmente retorna (sem chamar `yield` mais) — é assim que o `range` sabe que terminou.

## Pratique

1. **Reproduza**: rode `range-over-iterators.go` e identifique onde cada bloco da saída veio (lista, `Collect`, `SplitSeq`, Fibonacci).
2. **Modifique**: troque o `break` do Fibonacci por um limite de 10 iterações com contador; depois itere `strings.SplitSeq` com `range` e `break` no meio.
3. **Aplique**: dê à sua `List[T]` do exercício de generics um método `All() iter.Seq[T]` e percorra com `for range` — compare com a versão que retornava slice.
