Quando seu programa fala com uma API, um banco ou outro serviço, o formato mais comum de conversa é o **JSON**. Go serializa (`Marshal`) e desserializa (`Unmarshal`) com o pacote `encoding/json`, e a mágica é declarativa: com *struct tags* você diz qual campo vira qual chave — o pacote cuida do resto. A parte que exige atenção é o *caminho de volta*: JSON não tem tipos Go, e decodificar para `map` devolve números como `float64` e objetos aninhados como `any`.

## Marshal: struct → JSON (campos exportados + tags)

O `json` usa **reflexão**: ele inspeciona seu struct e serializa o que é exportado. Regras que valem ouro:

```go
type pedido struct {
    ID      string    `json:"id"`
    Cliente string    `json:"cliente,omitempty"` // omite se vazio
    Total   float64   `json:"total"`
    Criado  time.Time `json:"criado"` // time.Time tem formato próprio
}
```

- Campo minúsculo → **ignorado** em silêncio (não é erro — é dado perdido).
- Tag `json:"nome"` muda a chave; `omitempty` omite valores zero; `-` exclui o campo.
- `time.Time` serializa em RFC 3339 automaticamente; `[]byte` vira base64.
- **`nil` slice vira `null`, slice vazio vira `[]`** — a distinção que você viu em [Slices](slices), e que importa para APIs.

## Unmarshal: JSON → Go (e por que `map` é frágil)

JSON não conhece tipos Go: todo número é número, todo objeto é mapa. Ao decodificar para `map[string]any`, Go escolhe os tipos **genéricos**: `float64` para números, `[]any` para arrays, `map[string]any` para objetos. Acessar valores exige uma cadeia de type assertions — verbosa e frágil (um campo ausente derruba a assertion). É por isso que **decodificar direto para struct é o padrão**: o pacote casa chaves por tag, converte tipos e valida — e `json.Unmarshal` devolve erro se o JSON não bater com a estrutura.

## Marshal vs Encoder

- `json.Marshal(v)` → `[]byte`, para dados que você já tem em memória.
- `json.NewEncoder(w).Encode(v)` → escreve direto num `io.Writer` — respostas HTTP, arquivos, logs. É a forma usada nos handlers (página de [Servidor HTTP](http-server)).
- `json.NewDecoder(r).Decode(&v)` → lê de `io.Reader`, processando **streaming**: útil para JSON grande ou arquivos que não cabem na memória.
- Erros: **sempre** verifique o retorno de `Marshal`/`Unmarshal`/`Encode`/`Decode` em código real (os `_` aqui são por brevidade do exemplo). JSON inválido é `error`.

## Nota: `encoding/json/v2` (experimental)

Desde o Go 1.26 existe um `encoding/json/v2` **experimental** (ativado com `GOEXPERIMENT=jsonv2`) com API moderna (`MarshalWrite`, `UnmarshalRead`, tratamento de erros melhor). Não use em produção sem entender a flag — esta página ensina o `encoding/json` estável, que é o que o ecossistema usa hoje.

## Armadilhas comuns

- **Campo minúsculo "some" do JSON**: só campos exportados serializam. Debug de `{}` vazio geralmente é campo minúsculo.
- **Número decodificado em `any` é `float64`**: `int` grande pode perder precisão (acima de 2^53). Para inteiros exatos, decodifique para struct com campo `int64`, ou use `json.Decoder` com `UseNumber()`.
- **Type assertion sem `ok`**: `dat["num"].(float64)` pânica se a chave não existir ou o tipo for outro. Em dado desconhecido, use a forma segura `v, ok := x.(T)`.
- **Ignorar o erro do Unmarshal**: JSON malformado devolve erro; dados parcialmente preenchidos + erro ignorado = bug silencioso.
- **Depender da ordem das chaves**: JSON é um map — a ordem não é contrato. Compare conteúdo, não string.
- **Marshal de `map[string]any` com tipos mistos**: `json.Marshal` falha em `NaN`, `Inf` e valores sem suporte — trate antes.

## Pratique

1. **Reproduza**: rode `json.go` e explique por que `response1` e `response2` geram JSON diferentes.
2. **Modifique**: adicione `omitempty` num campo e um campo minúsculo; serialize e observe. Depois decodifique `{"page": "1"}` para `response2` — string em campo int devolve erro.
3. **Aplique**: defina `type produto struct` com tags, serialize uma lista para um `bytes.Buffer` com `Encoder`, e leia de volta com `Decoder` — o ciclo completo ida e volta.
