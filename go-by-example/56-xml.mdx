JSON domina as APIs modernas, mas o mundo legado ainda fala **XML**: SOAP, RSS/Atom, `pom.xml`, configs antigas. O pacote `encoding/xml` segue o mesmo modelo declarativo do JSON — struct + tags — com um vocabulário maior: além de elementos, você mapeia **atributos** (`id="27"`), nome de tag raiz e repetição de filhos.

## As direções das tags XML

| Tag | Efeito |
|---|---|
| `xml:"name"` | O campo vira um elemento filho ``<name>...</name>`` |
| `xml:"id,attr"` | O campo vira um **atributo** ``<plant id="27">`` || `xml:"plant"` em `XMLName` | Controla o nome do elemento em que o struct é serializado |
| `xml:",chardata"` | O campo recebe o **texto puro** do elemento |
| `xml:",any"` | Caso genérico para filhos desconhecidos |

Regra semelhante ao [JSON](json): só campos **exportados** participam; `time.Time` tem formato próprio; `MarshalIndent` só embeleza, não muda a estrutura.

## Unmarshal: do XML de volta para structs

O caminho inverso casa elementos e atributos com as tags — e aqui mora uma diferença do JSON: XML distingue ``<origin>`` repetido de ``<origins><origin>...</origin></origins>``. No exemplo, `Origin []string` com tag `xml:"origin"` lê **vários** ``<origin>`` irmãos; se o XML agrupasse, a tag seria outra. Quando o XML não casa com sua struct, o `Unmarshal` devolve erro — leia a mensagem e ajuste as tags.

## XML × JSON: quando usar cada um

- **JSON** para APIs novas, dados de aplicação — mais leve e legível (página [JSON](json)).
- **XML** para integração com sistemas legados (SOAP), formatos de config consolidados (Maven, .NET), RSS e feeds.
- Se o XML pode ser **enorme**, `xml.Decoder` com iteração por token processa em streaming (como o `Decoder` de JSON), sem carregar tudo na memória.

O mesmo conselho de sempre: para **HTML** (que parece XML mas não é), use `html/template` ou um parser de HTML — não `encoding/xml`.

## Armadilhas comuns

- **Esquecer o `XMLName`**: sem ele, o nome do elemento raiz vira o nome do tipo Go (`Plant`) — quase sempre errado.
- **Elemento × atributo**: `xml:"id"` gera ``<id>27</id>``; para ``<plant id="27">`` a tag é `xml:"id,attr"`. A diferença é um `,attr` — e o XML resultante muda completamente.
- **Campos minúsculos**: ignorados em silêncio, como no JSON. Debug de XML "vazio" = campo não exportado.
- **Repetição vs agrupamento**: `[]T` com `xml:"x"` lê ``<x>`` irmãos repetidos; não lê ``<xs><x/></xs>``. Confira a estrutura real do documento.
- **Namespaces**: XML com `xmlns:` exige tags com namespace (`xml:"ns tag"`); ignorar quebra o unmarshal de documentos reais.

## Pratique

1. **Reproduza**: rode `xml.go` e compare o primeiro bloco (sem header) com o segundo (com `<?xml?>`).
2. **Modifique**: adicione um campo `Preco float64 \`xml:\"preco\"\`` e um `EmEstoque bool \`xml:\"estoque,attr\"\`` a `Plant`; serialize e veja onde cada um aparece.
3. **Aplique**: escreva uma struct para ler um feed RSS simples (``<rss><channel><item><title>...``), com `Unmarshal` — e imprima os títulos com `range`.
