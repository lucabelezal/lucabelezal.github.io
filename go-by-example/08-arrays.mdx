Toda coleção em Go começa num conceito simples: o **array** — um bloco contíguo de N elementos do mesmo tipo, com tamanho **fixo** decidido na declaração. Você vai usar arrays raramente no dia a dia (os *slices*, na próxima página, dominam), mas entendê-los é entender a fundação: um slice é, por baixo, uma janela sobre um array.

## O tamanho é parte do tipo

`[5]int` e `[3]int` são **tipos diferentes** — não dá para atribuir um ao outro nem usar como se fossem o mesmo. Essa rigidez é proposital: o compilador sabe exatamente o layout de memória (5 × 8 bytes para `int64` em 64 bits) e o array cabe onde for declarado, sem alocação dinâmica. É também o que torna arrays inconvenientes para listas que crescem.

## Array é copiado por valor

Passar um array para uma função **copia todos os elementos** — a função recebe uma cópia e mudanças não refletem no chamador (mesma regra de [Ponteiros](pointers): se você quer mutar o original, passe `*[5]int`). Isso é caro para arrays grandes e é mais um motivo para preferir slices, que já carregam uma janela leve.

## Onde arrays aparecem de verdade

- Como **base dos slices**: todo slice aponta para um array interno (próxima página).
- **Buffers de tamanho fixo**: hashes `[32]byte`, chaves de criptografia, `[16]byte` de um UUID.
- Quando você quer valor pequeno e **comparável**: `a == b` funciona entre arrays do mesmo tipo (com elementos comparáveis) — coisa que slices **não** permitem.
- Structs pequenos e imutáveis que podem ser comparados/copiados como um todo.

No resto, o padrão Go é o **slice**.

## Armadilhas comuns

- **Indexar fora do limite**: `a[5]` num `[5]int` é *panic* em runtime (`index out of range`). Diferente de C, Go checa.
- **Achar que dá para crescer**: array tem tamanho fixo. Precisa de tamanho dinâmico? É slice.
- **Esquecer a cópia por valor**: mudar um `[5]int` dentro de uma função não muda o do chamador — e copiar arrays grandes a cada chamada custa caro.
- **Confundir `[5]int` com `[]int`**: o primeiro é um array (tamanho fixo, tipo inclui o tamanho); o segundo é um slice (dinâmico) — tipos completamente diferentes.

## Pratique

1. **Reproduza**: rode `arrays.go` e explique por que `idx:` imprime `[100 0 0 400 500]`.
2. **Modifique**: declare `c := [3]string{"a","b","c"}` e tente `c = [...]int{1,2,3}` — observe o erro de tipo. Depois some 4 ao índice 4 de `a` e observe o panic ao estourar o limite.
3. **Aplique**: escreva `func soma(arr [5]int) int` e depois `func zera(arr *[5]int)` — perceba a diferença entre copiar e apontar, e o porquê de os slices existirem.
