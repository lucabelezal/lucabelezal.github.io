A maioria das linguagens devolve **um** valor por função. Go devolve quantos quiser — e essa escolha simples sustenta o idioma mais famoso da linguagem: a função que retorna `(resultado, erro)`. Antes de chegar nos [Erros](errors), você precisa dominar o mecanismo: múltiplos valores de retorno e o identificador `_` para descartar.

## O uso que define Go: `(valor, erro)`

O padrão que você vai encontrar em quase toda função de Go é devolver o resultado **junto com um possível erro**:

```go
func buscarUsuario(id int) (Usuario, error) {
    // se algo falhar: return Usuario{}, err
    // se der certo:    return usuario, nil
}
```

Quem chama decide o que fazer com o erro — normalmente com um `if err != nil` logo na sequência (você já viu o formato em [If/Else](if-else), e a página de [Erros](errors) aprofunda). Isso substitui o mecanismo de *exceção* de outras linguagens: em Go, falha é um valor que transita pelo fluxo normal do código, não um desvio de controle escondido.

## Retornos nomeados

Além de devolver vários valores, você pode **nomear** os retornos na assinatura:

```go
func dividir(a, b int) (quociente, resto int) {
    quociente = a / b
    resto = a % b
    return // devolve quociente e resto (naked return)
}
```

Os nomes viram variáveis locais, já declaradas e zeradas. O `return` sem argumentos (*naked return*) devolve os valores atuais delas. Use com critério: em funções curtas os nomes documentam o que cada retorno significa; em funções longas, o `return` sem argumentos esconde o que está sendo devolvido e atrapalha a leitura.

## Armadilhas comuns

- **Contar retornos errado**: atribuir `a, b, c := vals()` quando a função devolve dois valores não compila (`assignment mismatch`). O compilador exige que a quantidade bata.
- **Declarar variável e não usar**: `a, b := vals()` seguido de código que nunca lê `a` é erro. Use `_` quando um retorno não interessa.
- **Achar que `_` é uma variável**: `_` não pode ser lido. Ele existe só para descartar.
- **Abusar de *naked return***: economiza uma linha, mas se a função tem 20 linhas, ninguém sabe o que volta. Nomeie retornos para clareza, não por preguiça.

## Pratique

1. **Reproduza**: rode `multiple-return-values.go` e explique por que `7` aparece duas vezes na saída.
2. **Modifique**: crie `func vals3() (int, int, int)` devolvendo três valores, atribua-os e imprima com `_` descartando o do meio.
3. **Aplique**: reescreva a função `dividir` com retornos nomeados e *naked return*, depois reescreva-a de novo com `return` explícito. Compare a legibilidade das duas versões.
