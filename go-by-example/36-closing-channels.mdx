Um channel comunica valores; o **`close`** comunica o fim: "não virá mais nada". Quem recebe enxerga o fechamento pelo segundo valor do receive — `v, ok := <-ch` com `ok == false`. É a forma de um produtor dizer aos consumidores que o trabalho acabou, sem enviar um valor especial de "fim".

    close(jobs)
    fmt.Println("sent all jobs")
    <-done
    _, ok := <-jobs
    fmt.Println("received more jobs:", ok)
}`}

## A regra de ouro: quem envia fecha

- **Quem cria e envia** num canal é quem o **fecha** — não o receptor.
- Receber de um canal fechado devolve o **zero value** imediatamente (com `ok == false`). Por isso `range` sobre canal fecha sozinho (próxima página).
- **Enviar num canal fechado dá panic**. Fechar duas vezes dá panic.

A regra de dono resolve: o produtor fecha quando termina de produzir; o consumidor nunca fecha o que não possui. É a mesma disciplina que você viu no checklist de [Ciclo de Vida de Goroutines](goroutine-lifecycle).

## `more` ou `range`?

As duas formas de consumir até o fim:

```go
for {
    j, ok := <-jobs      // controle fino (visto aqui)
    if !ok { break }
    ...
}
for j := range jobs {    // açúcar para o padrão acima
    ...
}
```

O `range` (próxima página) é a forma idiomática quando você só quer "todos os valores até fechar". A forma com `ok` dá controle (ex.: avisar outro canal — como o `done` aqui).

## Em código real

O par **produtor fecha / consumidor `range`** é o esqueleto de filas de trabalho: o [Worker Pools](worker-pools) usa `close(jobs)` exatamente assim. Channels de *broadcast* (fechar para liberar N goroutines ao mesmo tempo) também usam o close como sinal — sem enviar valor nenhum.

## Armadilhas comuns

- **Enviar depois do close**: panic em runtime. Garanta que nenhum produtor envia após o fechamento.
- **Fechar duas vezes**: panic. Um dono só, um close só.
- **Receptor que fecha**: quebra produtores que ainda enviam (panic). Receptor observa, não fecha.
- **Ler de canal fechado sem o `ok`**: recebe zero value **sem erro** — bug silencioso. Use `v, ok :=` ou `range`.
- **Close como "limpeza"**: não precisa fechar canais que o GC vai coletar — feche para **sinalizar fim**, não por higiene.

## Pratique

1. **Reproduza**: rode `closing-channels.go` e explique a última linha (`ok == false`).
2. **Modifique**: remova o `close(jobs)` — o worker fica preso esperando (deadlock no `<-done`). Depois envie após o close e veja o panic.
3. **Aplique**: reescreva o consumo do worker com `for j := range jobs`, mantendo o `done` — compare com a versão com `ok`.
