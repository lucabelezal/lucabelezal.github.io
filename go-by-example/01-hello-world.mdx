A primeira missão de quem aprende Go: fazer o programa falar. `Olá Mundo` parece trivial, mas carrega a estrutura mínima que todo executável Go exige — `package`, ponto de entrada e import. Entender essas três peças agora evita o primeiro erro de compilação sem explicação.

## Por que `main` aparece duas vezes?

Não é coincidência — são dois `main` com papéis diferentes:

- `package main` define o **tipo de artefato**: executável em vez de biblioteca.
- `func main` define o **ponto de entrada**: a função que o runtime chama ao iniciar.

Em uma biblioteca, o package tem outro nome (ex.: `package fmt`) e não existe `func main`. Um package `main` só serve para gerar um programa que roda de pé.

## Em código real

`go run` é o atalho de desenvolvimento: protótipos, exemplos e experimentos. Em produção, o fluxo típico é `go build` e distribuir o binário — ele roda sem Go instalado na máquina de destino. Programas de verdade raramente fazem tudo dentro de `main`: o `main` costuma ler configuração, montar dependências e chamar o resto do código.

## Armadilhas comuns

- Confundir `package main` (executável) com `func main` (ponto de entrada).
- Deixar um import sem uso: `imported and not used` é erro de compilação. Go trata código morto como erro de propósito.
- Achar que o nome do arquivo importa. Pode ser `hello.go`, `main.go` ou `x.go`: o que define o programa é o `package main` + `func main`.
- Usar `fmt.Print` no lugar de `fmt.Println` e estranhar a falta de quebra de linha — `Print` não adiciona nada; `Println` adiciona quebra.

## Pratique

1. **Reproduza**: crie `hello-world.go`, rode `go run hello-world.go` e depois `go build` + `./hello-world`.
2. **Modifique**: imprima seu nome. Depois chame `fmt.Println` duas vezes seguidas e observe que cada chamada quebra a linha.
3. **Aplique**: remova a linha `import "fmt"` e rode `go run`. Leia o erro de compilação — ele aponta exatamente o problema. Restaure o import depois.
