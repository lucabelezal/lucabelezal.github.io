Uma chamada externa que nunca responde trava seu programa. O padrão Go para "espero, mas não para sempre" é o `select` entre o resultado e um **`time.After`**: quem disparar primeiro vence. Timeout é só mais um caso no select.

import (

func main() {

    }()
    select {

        fmt.Println(res)
    case <-time.After(1 * time.Second):
        fmt.Println("timeout 1")

        c2 <- "result 2"
    }()

        fmt.Println(res)
    case <-time.After(3 * time.Second):
        fmt.Println("timeout 2")
    }
}`}

## O padrão

```go
select {
case res := <-resultado:      // a operação respondeu
    return res
case <-time.After(prazo):      // estourou o prazo
    return errTimeout
}
```

Dois detalhes que valem ouro:

- **O channel bufferizado** (`make(chan string, 1)`): se o timeout vencer e ninguém ler, a goroutine do trabalho ainda tenta enviar. Com buffer, o envio completa e a goroutine **termina sozinha** — sem vazar. Sem buffer, ela ficaria presa para sempre.
- **`time.After` cria um timer por chamada**: ótimo num `select` único; num laço, use `time.NewTimer` e `Stop` para não acumular timers.

## Em código real

Timeout protege toda operação externa: chamada de API, query de banco, leitura de socket. A forma moderna e preferida quando há `context` envolvido é `context.WithTimeout` (página [Context e Cancelamento](context-cancellation)) — que carrega o prazo pelas camadas. O `select` + `time.After` brilha nos casos pontuais, sem contexto.

## Armadilhas comuns

- **Channel sem buffer + timeout**: se o timeout vence, a goroutine que tenta enviar fica **presa** (vazamento). Buffer de 1 (ou `ctx`) resolve.
- **`time.After` num laço**: cada iteração cria um timer que só é liberado ao disparar — em laços longos, acumula. Use `NewTimer` + `Stop`.
- **Achar que timeout "cancela" o trabalho**: não cancela — só para de **esperar**. O trabalho segue rodando (por isso o buffer/ctx). Para cancelar de verdade, use `context`.
- **Prazo errado por unidade**: `time.After(1)` não compila? `1` é `int`; use `time.Second`/`time.Millisecond` (página [Time](time)).

## Pratique

1. **Reproduza**: rode `timeouts.go` e confirme que a primeira operação estoura e a segunda não.
2. **Modifique**: baixe o sleep do primeiro trabalho para 500ms — agora o resultado vence o timeout de 1s e a saída muda.
3. **Aplique**: reescreva o padrão com `time.NewTimer` num laço que tenta 3 vezes, cada uma com timeout de 200ms, até obter sucesso.
