Às vezes a melhor ferramenta para uma tarefa é um **programa externo**: rodar `git`, `ffmpeg`, `grep`, um script. O `os/exec` cria processos filhos — com controle total de entrada, saída, erro e código de saída. É o `subprocess` do Go, e a diferença crucial para quem vem de shell: **argumentos são uma lista**, não uma string — sem injeção por espaço maldoso.

## Output × Start + Wait

Duas formas de rodar:

| Forma | Quando |
|---|---|
| `cmd.Output()` | Só capturar o stdout; comando termina sozinho |
| `cmd.Start()` + pipes + `Wait()` | Trocar dados (stdin), ler enquanto roda, controlar o fim |
| `cmd.Run()` | Rodar e esperar, sem capturar (saída vai para o seu stdout/stderr) |

`cmd.CombinedOutput()` captura stdout **e** stderr juntos. Sempre espere o processo (`Wait`/`Output`/`Run`) para não virar *zumbi*.

## Por que argumentos como lista (segurança)

`exec.Command("sh", "-c", entradaUsuario)` é a porta aberta para injeção de comando — nunca faça isso com entrada de usuário. A forma segura é sempre lista:

```go
exec.Command("git", "commit", "-m", mensagem) // mensagem com espaços/; fica segura: é 1 argumento
```

Com lista, `"; rm -rf /"` vira **um argumento** do comando, não um novo comando. Se você precisa de shell (pipes, globs), monte a string com cuidado — mas prefira fazer pipes em Go com múltiplos `exec.Command`.

## Em código real

- `git`/ferramentas externas: `exec.Command("git", "status")` e parseie o stdout.
- Rodar scripts, compressores, conversores.
- `exec.CommandContext(ctx, ...)` cancela o processo quando o contexto dispara — essencial para não deixar filho pendurado (página [Context](context)).

## Armadilhas comuns

- **String de shell com input do usuário**: injeção. Lista de argumentos, sempre.
- **Não esperar o processo**: sem `Wait`, o filho pode continuar após o pai sair.
- **Ignorar o `ExitError`**: código de saída ≠ 0 é *falha*, não exceção. Cheque (e use `ExitCode()` para saber qual).
- **Deadlock com pipes cheios**: se o filho escreve muito no stdout e você nunca lê, ele bloqueia. Leia (ou use `Output`, que cuida disso).
- **Assumir o PATH**: `exec.Command("coisa")` depende do `PATH`. Para binário conhecido, use o caminho (via `exec.LookPath` — próxima página).

## Pratique

1. **Reproduza**: rode `spawning-processes.go` e explique por que `goodbye grep` não aparece.
2. **Modifique**: capture `git status` (ou `ls -la`) com `CombinedOutput` e imprima; depois rode um comando que falha e imprima o `ExitCode`.
3. **Aplique**: escreva um `grep` que recebe o padrão por argumento e lê de `os.Stdin`, passando os dados ao `grep` externo por pipe — comparando com o filtro de [Filtros de Linha](line-filters) em Go puro.
