Programa que roda em produção precisa **contar o que faz** — e logs são o único registro. A stdlib traz dois níveis: o **`log`** clássico (linhas de texto livre com data/hora) e o **`log/slog`** (logs *estruturados* em pares chave=valor, com níveis e saída em JSON — o padrão para serviços modernos que alimentam agregadores).

## `log` × `slog`: quando cada um

| | `log` | `log/slog` |
|---|---|---|
| Formato | Texto livre com prefixo | Estruturado (`chave=valor` / JSON) |
| Níveis | Não tem (só `Print`, `Fatal`, `Panic`) | `Debug`/`Info`/`Warn`/`Error` |
| Destino típico | `stderr`, arquivo | `stderr`, agregadores (Datadog, Loki) |
| Para quê | Scripts, ferramentas, protótipos | Serviços, produção, observabilidade |

O `slog` brilha onde o **agregador** consome: log em JSON com `level` e campos permite filtrar ("erros de pagamento nas últimas 2h") sem regex em texto. O `log` clássico continua ótimo para CLIs e ferramentas — a saída legível para humano é o recurso.

## Métodos que encerram: cuidado

`log.Fatal` loga e chama `os.Exit(1)`; `log.Panic` loga e entra em panic. São atalhos, mas **não rodam `defer`s** (o `Fatal` exit) e não são apropriados dentro de funções que deveriam devolver erro. Em código de biblioteca/serviço, logue o problema e retorne o erro — quem decide "morrer" é o topo.

## Em código real (serviços)

O padrão moderno de um serviço Go:

```go
logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
slog.SetDefault(logger)          // slog.Info(...) passa a usar o seu
logger.Info("servidor iniciou", "porta", 8080)
logger.Error("falha ao salvar", "err", err)
```

Inclua `err` como campo (o `slog` tem wrapper `slog.Any`/`slog.String` para valores especiais), use os níveis com critério e deixe o `log` de bibliotecas de terceiros ser redirecionado para o `slog` quando possível. Logging e erros andam juntos — o wrap de [Erros](errors) (`%w`) preserva a causa; o log registra onde ela chegou.

## Armadilhas comuns

- **Logar segredo**: `logger.Info("conectando", "password", senha)` joga a credencial no agregador. Nunca logue segredos.
- **`Fatal` no meio de uma função**: mata o processo sem `defer`. Em bibliotecas, retorne erro; deixe o `Fatal` para o `main`.
- **Mensagem sem contexto**: `"erro"` num log não ajuda. Inclua o que falhou e os valores relevantes (`slog` campos, ou `%v` no `log`).
- **Log de biblioteca no seu formato**: bibliotecas logam no logger padrão; redirecione (`log.SetOutput`/handler) para centralizar.
- **Ignorar níveis**: logar tudo como `Info` enterra o erro. Use `Error` para o que precisa de alerta, `Debug` para o ruído.

## Pratique

1. **Reproduza**: rode `logging.go` e identifique as linhas do `log` clássico e os dois JSON do `slog`.
2. **Modifique**: troque o handler do `slog` para texto (`slog.NewTextHandler`) e adicione `logger.Error("falha", "err", err)` com um erro de verdade.
3. **Aplique**: configure um logger `slog` JSON como default num mini-serviço e logue `"request recebido"` com campos `metodo` e `path` — depois use `DEBUG` (variável de ambiente, página anterior) para ligar/desligar `Debug`.
