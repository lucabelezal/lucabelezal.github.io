Templates, CSS, SQL, certificados de teste — arquivos que o programa precisa mas que **não deveriam depender do disco** na hora de rodar. A diretiva **`//go:embed`** resolve isso no tempo de **build**: o conteúdo vira parte do binário. Distribua um único executável; os arquivos vão junto — sem caminho relativo, sem `missing file` em produção.

## O que a diretiva faz (e o que ela não faz)

`//go:embed` é processada pelo **compilador**: no `go build`, o conteúdo dos arquivos vira parte do binário. No `go run`, funciona igual (compila para um executável temporário). Consequências importantes:

- O **binário é autocontido**: copie para um servidor sem os arquivos — os embutidos estão lá.
- O `embed.FS` é **somente leitura**: não dá para escrever nele. Para gerar conteúdo, leia e escreva em outro lugar (arquivo/`bytes.Buffer`).
- Os paths da diretiva são **relativos ao arquivo `.go`** que a declara — não ao diretório de trabalho. Não use `..` (a diretiva proíbe subir).
- O tamanho do binário cresce com o que você embute: embuta o necessário.

## `embed.FS` é um filesystem

O `embed.FS` implementa `fs.FS` — o mesmo contrato de `os.DirFS` e de filesystems zipados. Isso significa que você pode passá-lo para código que espera `fs.FS` (como `http.FileServer` ou `template.ParseFS`) e servir/processar os arquivos embutidos como se fossem do disco:

```go
templates := template.Must(template.ParseFS(arquivos, "templates/*.html"))
// http.FileServer(http.FS(arquivos))  → servir estáticos embutidos
```

(Página de [Servidor HTTP](http-server) mostra servir arquivos; `ParseFS` combina com [Templates](text-templates).)

## Em código real

- **Templates e estáticos** embutidos: um binário só para o deploy de uma aplicação web.
- **Config padrão + SQL de migração**: defaults que sempre existem, mesmo sem arquivos no servidor.
- **Testes**: fixtures sem depender do diretório de trabalho (que muda sob `go test ./...` de outra pasta).

## Armadilhas comuns

- **Esquecer o import**: `//go:embed` com `embed.FS` exige `import \"embed\"`; para `string`/`[]byte`, o import em branco `_ \"embed\"` é obrigatório se você não usa o pacote.
- **Path relativo ao `.go`**: o pattern `folder/single_file.txt` resolve a partir do arquivo-fonte, não do `cwd`. Rodar de outra pasta não quebra — justamente o objetivo.
- **Arquivo não encontrado**: `//go:embed` com path inexistente é **erro de compilação** (o build falha). Bom: pega cedo. Pattern com wildcard que não casa também falha.
- **`..` e absolutos**: a diretiva proíbe `..` e `/` no início. Se você quer "a pasta acima", reorganize.
- **Tentar escrever no `embed.FS`**: é read-only; não há `WriteFile`. Leia e copie.

## Pratique

1. **Reproduza**: crie `folder/single_file.txt`, `folder/file1.hash`, `folder/file2.hash` e rode `embed.go` — depois apague a pasta e rode de novo (funciona: está no binário).
2. **Modifique**: embuta um template `templates/ola.html` num `embed.FS` e execute com `template.ParseFS`.
3. **Aplique**: escreva uma função que serve um arquivo embutido (`dados.json`) como `[]byte` para o código processar, sem tocar o disco.
