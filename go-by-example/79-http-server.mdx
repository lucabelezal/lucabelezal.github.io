O outro lado do `net/http`: um **servidor HTTP**. A peça central é o *handler* — uma função que recebe o pedido e escreve a resposta. O `http.HandleFunc` registra handlers no mux padrão e o `ListenAndServe` põe o servidor no ar. E o detalhe que muita gente descobre tarde: **cada request roda numa goroutine própria** — o servidor é concorrente de graça.

## Anatomia de um request

O servidor `net/http` faz por você: aceita a conexão TCP, parseia a requisição HTTP, monta o `*http.Request` e chama o handler **numa goroutine nova** (por isso N requests simultâneos não se bloqueiam — relembre [Goroutines](goroutines)). O handler só precisa:

1. Ler o que precisa do `req` (`req.Method`, `req.URL.Path`, `req.Header`, body).
2. Escrever a resposta no `w` (`fmt.Fprintf`, `json.NewEncoder(w).Encode`).
3. Definir o status se não for 200 (`w.WriteHeader(http.StatusNotFound)`).

## Handler = função que vira interface

`HandleFunc` é o atalho do padrão que você viu em [Interfaces](interfaces): a stdlib define `type HandlerFunc func(ResponseWriter, *Request)` com um método `ServeHTTP` que chama a função — então uma **função implementa a interface** `http.Handler`. É por isso que `HandleFunc("/x", minhaFuncao)` aceita a função direto. Se você tem um tipo com `ServeHTTP`, registre com `http.Handle`.

## Timeouts: o servidor padrão também precisa

Assim como o cliente, o `http.Server` padrão de `ListenAndServe` não configura timeouts — um cliente lento pode segurar recursos. Para produção, monte um servidor explícito:

```go
srv := &http.Server{
    Addr:              ":8090",
    Handler:           mux,
    ReadHeaderTimeout: 5 * time.Second,
}
log.Fatal(srv.ListenAndServe())
```

E para encerrar com **graceful shutdown**, o padrão de [Sinais](signals) + `srv.Shutdown(ctx)` — a página de [Context](context) mostra o cancelamento por request.

## Em código real

- Rotas: o mux padrão serve para APIs pequenas; `http.ServeMux` moderno (Go 1.22+) aceita patterns com método (`"GET /hello"`) e wildcards. Para rotas complexas, frameworks (`chi`, `gin`, `echo`) — mas a base é esta.
- **JSON**: `json.NewEncoder(w).Encode(meuValor)` responde JSON (página [JSON](json)).
- **Arquivos**: `http.FileServer(http.Dir("static"))` serve estáticos; `http.FS` com [embed](embed-directive) serve do binário.
- **Middlewares** (log, auth) são handlers que envolvem handlers — a composição de funções de [Funções](functions) em ação.

## Armadilhas comuns

- **Escrever depois do status**: uma vez que você escreve o body, o status 200 já foi enviado. Defina `WriteHeader` **antes** de escrever (ou use `http.Error`).
- **Ler o body e não fechar**: `req.Body` precisa ser fechado (ou o `net/http` fecha ao final — mas feche explicitamente em handlers longos).
- **Achar que um request trava os outros**: não — cada handler roda em goroutine. Mas **estado compartilhado** entre handlers precisa de mutex (página [Mutexes](mutexes)).
- **Handler que bloqueia sem timeout**: uma chamada externa sem `ctx`/timeout segura a goroutine do request. Use [Context](context).
- **`ListenAndServe` erro ignorado**: porta ocupada devolve erro e o programa "morre" sem explicação. `log.Fatal(srv.ListenAndServe())`.

## Pratique

1. **Reproduza**: suba o servidor, `curl /hello` e `curl /headers`, e derrube.
2. **Modifique**: adicione `GET /soma?a=2&b=3` que lê `req.URL.Query()`, soma e responde o número (use `strconv`).
3. **Aplique**: responda JSON (`json.NewEncoder`) num endpoint e crie um middleware de log que envolve um handler e imprime `método path` antes de chamar o próximo.
