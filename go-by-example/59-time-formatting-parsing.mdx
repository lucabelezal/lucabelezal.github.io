Se você vem de outras linguagens, espera máscaras tipo `yyyy-MM-dd`. Go faz diferente: **os layouts são datas de exemplo** — você escreve um padrão usando o *horário de referência* `Mon Jan 2 15:04:05 MST 2006` (ou `01/02 03:04:05PM '06 -0700`). O mesmo layout serve para `Format` (Time → string) e `Parse` (string → Time). É estranho no começo e natural depois.

## O horário de referência (decore este mnemônico)

`01/02 03:04:05PM '06 -0700` — o dia 2 de janeiro de 2006, às 3:04 da tarde. Cada parte é um componente:

| Token | Significa |
|---|---|
| `2006` / `06` | ano (completo / 2 dígitos) |
| `01` / `1` / `Jan` / `January` | mês (zero, sem zero, abreviado, completo) |
| `02` / `_2` / `2` | dia (zero, com espaço, sem zero) |
| `15` / `03` / `3` | hora (24h / 12h com zero / 12h sem zero) |
| `04` / `4` | minuto |
| `05` | segundo |
| `PM` | am/pm |
| `-0700` / `-07:00` / `MST` | fuso (numérico, com dois-pontos, por nome) |
| `.000` / `.999` | fração de segundo (zeros fixos / opcionais) |

Não é uma máscara com letras mágicas — é um **exemplo** que o Go lê. Se você escrever `YYYY-MM-DD`, vira literal (imprime "YYYY-MM-DD") porque não é o formato de referência. É o erro nº 1 de quem migra.

## Formatar × parsear

A mesma string de layout vai nos dois sentidos: `t.Format(layout)` produz; `time.Parse(layout, s)` consome. Prefira as constantes prontas quando possível: `time.RFC3339`, `time.RFC1123`, `time.Kitchen` (`3:04PM`), `time.DateTime` (`2006-01-02 15:04:05`).

Detalhe de parsing: se o layout **não tem fuso**, o resultado assume **UTC**. Se tem fuso nomeado (`MST`), precisa do nome conhecido. Para controlar, parseie e depois `.In(fuso)`.

## Em código real

- **APIs**: RFC3339 (`time.RFC3339`) é o formato do ISO 8601 usado na web. `MarshalJSON` de `time.Time` já serializa assim (página [JSON](json)).
- **Guardar em banco**: prefira RFC3339 UTC ou epoch inteiro; guardar string formatada por fuso local é bug garantido.
- **Logs**: timestamps consistentes (`time.DateTime` + fuso fixo) facilitam grep.

## Armadilhas comuns

- **`yyyy-MM-dd` não funciona**: layouts Go usam o horário de referência. Use `2006-01-02` (constante `time.DateTime` para incluir hora).
- **Parse sem fuso vira UTC**: `"2012-11-01 22:08:41"` parseado vira UTC, não local. Se o dado é local, anexe o fuso ou use `.In()`.
- **Parse parcial**: layout sem ano/mês/dia devolve ano 1/dia 1 (visto no exemplo) — raramente o que você quer para armazenar.
- **`.999` vs `.000`**: `.999` omite fração zero (`...47`); `.000` fixa (`...47.000`). Escolha conforme o formato esperado.
- **Ignorar o erro do Parse**: string que não casa devolve erro (e o Time resultante é o zero). Trate ou valide a entrada.

## Pratique

1. **Reproduza**: rode `time-formatting-parsing.go` e identifique cada token do layout na saída.
2. **Modifique**: formate `t` como `02/01/2006 15:04` (dia/mês/ano brasileiro) e parseie `"17/11/2009 20:34"` de volta — confira que o layout casa nos dois sentidos.
3. **Aplique**: escreva `func paraRFC3339(s string) (string, error)` que aceita `2006-01-02 15:04:05` e devolve RFC3339 — tratando o erro de parse.
