An HTTP API in Go needs four things: listening on a port, routing paths to functions, reading/writing JSON, and logging with identity. The stdlib has delivered all four since Go 1.22 — no framework. Let's build in that order, one layer at a time, each running before the next.

## 1. Context

Frameworks solve what the stdlib has solved since 1.22: routing by method and pattern, serving with timeouts, draining shutdown. Start stdlib: fewer layers to debug, break-free upgrades. Frameworks enter when it genuinely hurts (complex validation, generated OpenAPI) — not before.

![Diagram: request crosses middleware, handler, JSON back](/img/diagramas/go-http-cadeia.svg)

## 2. The problem

APIs without request_ids: three requests fail together and logs can't tell which is which. Without timeouts: slow handlers hold connections forever. Without Content-Type: clients guess bodies. Each has taken down real production — none needs a framework.

## 3. Step 1 — the smallest responding server

```go title="main.go" showLineNumbers
package main

import "net/http"

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
		w.Write([]byte("ok"))
	})
	http.ListenAndServe("127.0.0.1:18098", mux)
}
```

Three pieces, nothing else:

- **`http.NewServeMux()`** — the router: a path → function table.
- **`HandleFunc("GET /health", func...)`** — registers a route. The leading `"GET "` (Go 1.22+) splits by method: same path, different methods, different functions.
- **The handler function** — always `func(w http.ResponseWriter, r *http.Request)`: `w` is where the response leaves, `r` is what arrived.

```bash title="Terminal"
$ curl http://127.0.0.1:18098/health
ok
```

Server live. Everything else in this post is layers over these 10 lines.

## 4. Step 2 — real JSON

Plain text isn't an API. Swap the response for JSON and add a POST route reading JSON:

```go title="main.go" showLineNumbers
mux.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(map[string]string{"status": "ok"})
})
mux.HandleFunc("POST /double", func(w http.ResponseWriter, r *http.Request) {
	var in struct{ N int `json:"n"` }
	if err := json.NewDecoder(r.Body).Decode(&in); err != nil {
		http.Error(w, "json inválido", http.StatusBadRequest)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(map[string]int{"result": in.N * 2})
})
```

Two rules avoiding classic bugs:

1. **Content-Type before the first `Encode`.** After the first byte leaves, headers lock — clients without Content-Type guess bodies (and proxies rewrite).
2. **Invalid JSON = honest 400**, not 500. 400 says "your request is wrong"; 500 says "I broke". Mixing them corrupts alerts and dashboards.

```bash title="Terminal"
$ curl http://127.0.0.1:18098/health
{"status":"ok"}
$ curl -X POST http://127.0.0.1:18098/double -d '{"n":21}'
{"result":42}
$ curl -X POST http://127.0.0.1:18098/double -d 'xxx'
json inválido
```

## 5. Step 3 — middleware: which request is which

With two routes, logs already blur together. Middleware fixes it: a function wrapping the router, stamping `request_id` and timing:

```go title="main.go" showLineNumbers
func mw(log *slog.Logger, next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := fmt.Sprintf("req-%d", time.Now().UnixNano()%100000)
		ctx := context.WithValue(r.Context(), reqKey, id)
		l := log.With(slog.String("request_id", id))
		start := time.Now()
		next.ServeHTTP(w, r.WithContext(ctx))
		l.Info("done", slog.String("method", r.Method), slog.String("path", r.URL.Path), slog.Duration("ms", time.Since(start)))
	})
}
```

Read inside out: generates `id`, hangs it on `ctx` (handlers below read it with no extra parameter), derives a logger with the id, notes the clock, **calls the next layer**, logs method + path + duration. Middleware is an onion: request_id first (everything below logs with it), recovery outside everything.

```bash title="Terminal"
{"level":"INFO","msg":"done","request_id":"req-69000","method":"GET","path":"/health",...}
{"level":"INFO","msg":"done","request_id":"req-20000","method":"POST","path":"/double",...}
```

Three requests, three identities — logs now answer "which one failed".

## 6. Failures and trade-offs

**Frameworks on day one.** Chi/Gin/Fiber before the first pain: layers to debug, breaking upgrades, convention lock-in. Adopt when the stdlib proves limits.

**No server timeouts.** Handlers with `ctx` don't save connections without `ReadTimeout`/`WriteTimeout` on `http.Server`: Slowloris holds workers for free. Timeouts on both ends + graceful shutdown (the concurrency post's real `main`).

**`request_id` generated in handlers.** Too late: earlier middlewares already logged without it. Generate at the edge (first middleware), propagate via `ctx`.
