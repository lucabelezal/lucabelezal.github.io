## 1. Context

`go test` runs `*_test.go` files, cached by default, `-count=1` to force. Convention: `TestXxx(t *testing.T)` functions, `t.Fatalf` for failing with messages, `t.Run` for subtests. Tables = slices of `{name, in, want}` structs: adding cases means adding rows, no new functions.

## 2. The problem

Single-example tests rot: they cover the happy path, hide edges (empty, nil, zero), and when they break nobody knows which case. Worse: concurrency without `-race` passes green with hidden races — the detector exists precisely because human eyes can't catch interleavings.

## 3. Mental model

**Cases are data, not code.** Tables separate *what* (rows) from *how* (runner). Case names become executable documentation (`TestSum/vazio` — well, `/empty`).

**`-race` instruments, doesn't guess.** It tracks cross-goroutine accesses at runtime; costs ~10x — hence CI, not production.

**Test observable behavior.** Logs (fields, redaction), goroutine counts, outputs — not internals. Refactoring without breaking tests proves the tests target the contract.

![Diagram: case table feeding subtests, -race on top](/img/diagramas/go-testes-tabela.svg)

**Rule of thumb.** New bug → new table case first (reproduces), then the fix. Tables grow with incidents.

## 4. Implementation

```go title="sum_test.go" showLineNumbers
func TestSum(t *testing.T) {
	tests := []struct {
		name string
		in   []int
		want int
	}{
		{"vazio", nil, 0},
		{"um", []int{5}, 5},
		{"varios", []int{1, 2, 3}, 6},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			if got := Sum(tt.in); got != tt.want {
				t.Fatalf("Sum(%v) = %d, want %d", tt.in, got, tt.want)
			}
		})
	}
}
```

Full CI command: `go test -race -count=1 ./...` — no cache, detector on, everywhere. For logs: handlers into `bytes.Buffer` + `json.Unmarshal` asserting `order_id` and `[REDACTED]` (the errors post's pattern). For leaks: `runtime.NumGoroutine()` before/after the scenario (the concurrency post's pattern: 1 → 1).

## 5. Failures and trade-offs

**Testing implementation.** Asserting internal calls or lock order breaks on every honest refactor. Target outputs and effects.

**`time.Sleep` to synchronize tests.** Flaky by construction: breaks on slow CI, wastes on fast CI. Synchronize with channels/`Wait`/contexts with timeouts — never guesses.

**Coverage as goal.** 100% with empty asserts lies better than honest 70%. Coverage guides where cases are missing; proves nothing alone.

**Testing third parties.** Mocking libraries to assert their behavior tests the mock. Test your integration (the contract you use), not the lib.
