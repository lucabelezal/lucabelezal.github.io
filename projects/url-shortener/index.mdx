Encurtador de URL é a pergunta de aquecimento clássica de system design. Parece trivial — guarda um par de URLs e redireciona — e é justamente por isso que serve de teste: quem só vê "duas colunas numa tabela" perde a chance de mostrar estimativa, particionamento e cache.

Este projeto percorre o caminho completo, um passo por vez. Cada capítulo fecha uma decisão antes de abrir a próxima.

## O que vamos construir

Um serviço que recebe uma URL longa e devolve uma curta que redireciona para a original.

1. [O problema](/projects/url-shortener/o-problema) — o que é, e as perguntas que fecham o escopo.
2. [Estimativa de capacidade](/projects/url-shortener/estimativa) — quantas escritas, leituras e quanto storage; o que cada número decide.
3. [Design de alto nível](/projects/url-shortener/design-alto-nivel) — endpoints, 301 vs 302 e a função de hash.
4. [Deep dive](/projects/url-shortener/deep-dive) — modelo de dados, gerador de ID, base 62 e os fluxos.
5. [Fechamento](/projects/url-shortener/fechamento) — o que ficou de fora e o que aprofundar.

## Como ler

Cada capítulo assume o anterior. A ordem não é decorativa: a estimativa define o schema, o schema define a função de hash, a função de hash define o fluxo.
